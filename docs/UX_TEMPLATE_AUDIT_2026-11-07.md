# 上线后 UX 与 Website 模板评估

日期：2026-11-07。站点：https://designlibrary.grownotic.com/

## 检查范围与结论

实际浏览桌面资源列表、Modern SaaS 预览 / Export / Compare、390px 手机列表与 Restaurant Warm 预览、中文搜索及 Guide。另静态扫描全部 82 套模板的声明页面和内部页面占位引用，重点阅读 8 套模板的相关页面。不是对全部模板的浏览器、无障碍或生产功能认证。

适合继续沿用当前资源库布局。主要提升方向是更快找到、准确判断能力、更容易导出和接入。模板应以核心用户旅程的完成度衡量，不能只按页面数量衡量。

源文件检查结果：

- 82 套模板，共声明 1,288 个页面；未发现声明页面缺文件，未发现 `{{p:slug}}` 指向未声明页面。
- 页面、nav、footer 中合计有 130 个 form，其中 95 处使用 `onsubmit="return false"`。这说明大量表单是演示或待集成，不能据此断言其它 35 个已经可真实提交，也不能把禁止默认提交一概视为 bug（可能还有 JS 处理）。
- 有 360 处 `href="#"`，其中可能包括菜单开关等合理用途；不能把此数直接当坏链数量。需逐一核对按钮语义与行为，Modern SaaS 的 Log in 已见该占位。

## 网站布局：保留框架，减少浏览负担

1. 手机顶部过高：导航、领域切换、搜索、分类、介绍和场景入口叠在卡片前。实看第一张卡片标题要继续下滚才出现。手机介绍压成一句，把详细帮助放在「怎么用」；优先保留搜索、类别、筛选和结果数。
2. 桌面左栏包含很长的 Industry / Style 清单。保留分类，但默认显示常用项 + 展开全部，并给分类项搜索；已选条件始终显式显示，避免滚动后忘记当前限制。
3. 部分中文说明的颜色与字号偏弱，建议加强关键信息层级；这是视觉观察，尚未测量实际对比度。可选中文 / English 展示，减少每段双语重复，而非删除中英文搜索支持。
4. 卡片优先展示：预览图、名称、用途、主要能力与准备程度。「22 pages」不足以证明比「10 pages」更完整。页数降为辅助信息，加入 responsive / demo / integration required 等真实能力标签。
5. 图片型行业需要更可替换的主视觉结构与缩略图。区分 intentional illustration 与 placeholder，不把所有自绘 SVG 一律改成照片；图片位置应有比例、建议尺寸和裁切说明。

## 已复现问题：Compare 在手机上无法关闭

复现步骤：桌面打开 Modern SaaS → 开启 Compare → 返回列表并打开另一模板 → 切到 390px。

实际：Original / Your version 继续左右并列，每个 iframe 约 194.5px；小屏工具栏隐藏 Compare 按钮，用户无法就地关闭。Restaurant Warm 的标题因此挤成极窄的多行。

源码线索：`build/src/app.css` 小屏规则隐藏 `.vbar [data-cmp]`，`build/src/app.js` 仍按 `S.cmp` 渲染双栏。

建议：小屏自动使用单栏，并显示「原版 / 我的版本」切换；或直接关闭比较且保留能退出的按钮。宽度变化和模板切换都要检查状态，不只测试刷新进入。

现有 Compare 是同一条目的 Original / Your version，并不是两套不同模板的比较。可改名「对比修改」，未来另做最多 2–3 套模板的选择比较，避免两个用途混淆。

## 功能优先级

| 优先级 | 建议 | 验收 |
|---|---|---|
| P0 | 修复手机 Compare 状态 | 桌面开启后缩窄、切换模板、返回再进入，始终能正常单栏浏览和退出 |
| P0 | 给模板标注演示 / 待接入能力 | 注册、预约、购物、付款等在下载前可见限制，不把静态外观描述成生产服务 |
| P1 | 简化手机首屏和预览工具栏 | 主路径只有选页面、预览、定制、导出；次要操作收入更多菜单；进入后能更快看到模板名称与预览 |
| P1 | Guide 重排为普通使用优先 | 浏览 → 搜索 → 收藏 → 下载 → AI 复用；MCP / API 进入进阶章节；保留无需 MCP 的路径 |
| P1 | 搜索明确范围 | 当前类别显示命中数，提供全库分组结果；输入词、清除搜索、空结果和返回状态明确；中文“餐厅”已实测有 9 个结果，保留该能力 |
| P1 | My list 项目化与备份 | 命名集合、备注、JSON 导出/恢复；声明只存此浏览器；先不强制登录 |
| P1 | Export 用选择目的引导 | 静态 HTML / Hostinger PHP / Elementor 重建参考 / AI JSON；主按钮推荐适合的格式；Elementor 不能原生导入的说明放在选项旁 |
| P1 | 单条目使用说明 | 展示用途、哪些可定制、页面、依赖、可复制区块、限制和接入步骤；不用打开另一份源码才能判断 |
| P2 | 真实更新时间排序 | Newest 当前是数组逆序，增加真实日期或更准确改名；缺日期不补造 |
| P2 | 条目之间关联与区块复用 | 从模板跳到相关 effect，单独复制 Hero、Pricing、FAQ 等区块，并带必要 CSS / JS / 变量说明 |

| Grow Notic (`grownotic`) | contact 有邮箱待填、待确认字段及接 CF7/SMTP 的说明；按钮为 type=button，尚非真实询盘流程 | 先做完整的 agency 模板版本：项目详情、服务范围、案例成果占位和询价演示；将集成任务列进说明文件，不让最终客户界面长期显示开发备注 |

| Blue Hour (`blue-hour`) | 页面和设计说明主打滚动、光标跟随、图像波动等沉浸效果；本轮未做其性能与 reduced-motion 实测 | 作为进阶展示模板保留；另验证触屏替代、减少动态效果、无 JS 基本阅读及图片替换后的速度，补性能/依赖标签；不优先继续加动画 |

## 每套模板的“完善”应满足什么

- 页面层：必要页面完整，导航清楚；不要强制所有模板都出现 404、Coming soon、Gallery 等演示目录项在客户导航里。完整 sitemap 可放预览器。
- 流程层：主要 CTA 名称与目的地一致；演示的输入、成功、失败、空状态可理解；实际后台能力另列集成要求。
- 内容层：示例数据自洽，价格计算正确，没有未标注的真实业绩承诺；有明确替换位置与素材要求。
- 组件层：表单 label / name / autocomplete / validation、按钮语义、焦点状态、菜单键盘和触屏能力完整。
- 导出层：实际打开下载包验证，避免只验 iframe；HTML 与 PHP 功能说明准确，Live 预览增强与模板自带动效区分。
- 发布层：按页面设置 title / description / 语言和分享信息；当前 `page_file()` 的 HTML 导出固定 lang=en 且未输出独立 meta description，后续应随客户内容设置。

建议对每套分别标记 Layout ready、Interactive demo、Integration required、Tested date。不要用单一 Ready 暗示模板已包含后台、支付、邮件和业务数据。

## 建议实施批次

第一批：Compare 修复 + 手机首屏压缩 + 演示功能标识 + Modern SaaS CTA / Restaurant Warm 金额及重复页名。

第二批：详情使用说明 + Export 引导 + Guide + My list 备份。

第三批：选择 Modern SaaS、Restaurant Warm、Smile Dental、Oakline Furniture、Grow Notic 各打造一套完整的行业示范，再以同样的验收要求扩展其它模板。
