# Design Library — 给 Claude Code 的说明

这是设计母版库：先挑模板 / 效果 / 转场 / 平面设计配方，再动手，避免从空白「凭感觉设计」。分 Website 和 Graphic 两个领域。
内容全部在 `library/`（Website：模板 82 · 效果 122 · 页面转场 22；Graphic：平面设计 5 · 素材 73（另有本地 local_only 素材）；色板 100 共用），机器可读目录见 `library/catalog.json`，总索引见 `library/INDEX.md`。

## 两个领域：Website / Graphic
库分成两个领域（catalog 里每项都有 `domain` 字段，网站顶部有 Website / Graphic 开关）：
- **website**：`library/templates`、`effects`、`transitions`、`kits`、`theme-parts`（模板 / 效果 / 页面转场 / Elementor）。
- **graphic**：`library/graphics/<slug>/`（海报 poster · 缩略图 thumbnail · 横幅 banner · 社交帖 social · 产品图 product）。
- `palettes`（色板）和 `taxonomy.json`（风格 / 行业）两边共用。
- 物理目录没有搬动（避免破坏路径和工具），靠 `domain` 字段 + 网站开关 + `INDEX.md` 分区来区分。

## 素材库 Assets（Graphic 领域）
一张好看的图不是「用代码画出来」，而是**多层素材叠出来**：实拍抠图 / 背景图 + 线条、边框、形状 + 纹理叠层 + 排版。所以先有素材库，再做图。
- 位置：`library/assets/<类别>/<slug>/{asset.json, <文件>}`；类别见 `taxonomy.json` 的 `asset_cats`：line shape frame sticker icon texture background photo cutout mockup logo。
- 现有（自有 SVG，可公开）：线条 13 · 形状 18 · 边框 9 · 贴纸徽章 6 · 图标 15 · 纹理 6 · 背景 6，由 `py tools/gen_assets.py` 生成。SVG 全部用 `currentColor`，内联后用 CSS `color` 换色；纹理用 `mix-blend-mode` 叠在图上。
- **收新素材**：把照片 / 抠图 / 样机 / logo 先放 `_work/inbox/assets/`，确认授权后：
  `py tools/ingest_asset.py <文件或文件夹> --cat cutout --tags gpu,hardware --license local_only --source "来源"` 然后 `py build\build.py`。文件夹 = 批量，同一类别同一组标签。
- **授权**：自己拍的 / 自己做的 / 明确可再分发 → `--license ok`（进 `public_html`，网站可预览）；图库（Unsplash / Pexels / Pixabay）、Canva、Envato、客户 logo → `--license local_only`（默认，只留本地，不进 `public_html`，Claude Code 通过 `library/catalog.json` 和 MCP 读取）。授权不明的不入库。
- **MCP**：`search_library(kind='asset', query='arch frame')` → `get_asset(slug, color='#FF6A00')`（SVG 返回源码，位图返回本地路径）→ `export_asset(slug, dest_dir)`。
- **做图时**：先按配方选 3–6 个素材（一个主视觉 photo/cutout + 背景 + 线框 + 纹理），再写排版；位图素材要复制到项目的 `assets/` 里引用；用到 `local_only` 素材的成品不要放进公开仓库。没有合适素材的位置标「缺图」告诉用户，不要用 CSS 硬画写实物体（像显卡、人物、球），会显得假。
- 网站：Graphic → Assets，按类别筛选，点开可换色、复制 SVG、下载。

## Graphic（平面设计）怎么用
- 每张图 = `library/graphics/<slug>/{graphic.json, graphic.html, DESIGN.md}`：`graphic.html` 是固定画布尺寸的 HTML/CSS（颜色字体只用 `--c-primary --c-secondary --c-text --c-accent --c-surface --c-border --on-primary --on-secondary --on-accent --on-surface --f-head --f-body`）；`DESIGN.md` 是**设计配方**（构图特征 + 不要清单 + 文案口吻 + 中文版 + 用法）。
- MCP：`search_library(domain='graphic', graphic_type='poster', style='swiss')` → `get_graphic(slug, format='doc')`（做新图前必读）/ `format='html'`（可传 primary…border、heading_font、body_font）→ `export_graphic(slug, dest_dir, …)`。没有 MCP：读 `library/catalog.json`（`kind='graphic'`）或 `/api/graphic/designs/<type>/<slug>.json|.html`、素材 `/api/graphic/assets/<类别>/<文件>`。
- **做新图的规则**：照配方做一张**全新**的图，不要抄原图；文案换成客户的，没有素材的位置标「缺图」；颜色字体只走 CSS 变量；中文配 Noto Sans SC / Noto Serif SC，中文标题不要斜体；最后用浏览器按画布尺寸截图（视口 = 画布宽高）导出 PNG。
- 新增一张图：建 `library/graphics/<slug>/`，`graphic.json` 字段 `slug name zh tag type size{label,w,h} styles industries colors{6} fonts{head,body} license`；`type` 只能用 `taxonomy.json` 的 `graphic_types`（poster thumbnail banner social product）；风格 / 行业 ID 同网站线；把 slug 追加到 `library/graphics/order.json`；跑 `python build/build.py`。**必须与已有图明显不同**（类型 × 风格 × 构图），并在回复里写一句「与最接近的已有项相比，不同在哪」。
- **在 Canva 里做图**：用户用 **Claude Desktop 连接 Canva**（不在 Claude Code 里连）。网站里每张图的 Export › **Copy Canva prompt**（或 MCP `get_graphic(slug, format='canva')`）会生成一段带尺寸、色值、字体和完整配方的提示词，用户贴进 Claude Desktop 让它在 Canva 里做出全新的设计。Claude Code 这边不需要 Canva 连接。
- **Canva 来源**：Canva 的模板 / 素材受 Canva 内容许可约束，不可转售、不可公开分发。不要把 Canva 模板原样收进库；只收「设计配方」（尺寸、构图、配色、字体、文案口吻），自己重新用 HTML/CSS 画。需要保留参考截图时放 `_work/inbox/canva/` 或 `license: local_only`（不进 `public_html`）。用户自己的 Canva 设计可以作为参考，但仍要确认其中的素材授权。

## 两条线（Website 领域内的技术路线）
- **web**：手写 HTML/CSS/JS/PHP 站。整套模板可直接导出成 HTML 站或 PHP 站。
- **elementor**：Elementor/WordPress 站。取 Global Colors/Fonts 设定值（用户手动填入 Site Settings，Claude 不代改）+ prompt + 参考 HTML；整站 kit / 零件在 `library/kits`、`library/theme-parts`（Envato 来源，local_only）。

## 优先用 MCP（如果已注册 design-library）
`library_overview` → `search_library` → `get_template` / `get_page` / `export_site` → `get_effect` / `get_transition` / `get_palettes` → `get_elementor_item`；平面设计：`get_graphic` / `export_graphic`。
- `search_library(kind='template', industry='restaurant', style='elegant', site_type='ecommerce')`：按行业/风格/站型找。
- `export_site(slug, dest_dir, ext='php'|'html'|'elementor'|'json', 自定义值…)`：把整个模板一次写进用户的项目文件夹（`dest_dir` 必须是绝对路径，已存在的文件默认不覆盖）。
- 自定义值：`primary secondary text accent surface border heading_font body_font text_scale radius_px section_padding('96px'|'110%') content_width('1300px'|'90%') page_transition transition_ms`。**客户的品牌色/字体一律用这些参数传入，不要导出后手改 hex。**
- `get_palettes(category)` 选好色板，把六个色值传给上面的参数。
没有 MCP 时：读 `library/catalog.json`，再读对应 `TEMPLATE.md` / `EFFECT.md`；或用网站 `/api/`（`/api/catalog.json`、`/api/website/templates/<大组>/<slug>/<slug>-php-site.zip` 等）。

## 做设计时必须遵守
1. 先读所选模板的说明：有 `library/styles/<slug>/DESIGN.md` 的先读（`get_template(format='doc')`）——**构图特征**和**不要**清单是这套风格的灵魂，不是可选项。
2. 颜色、字体、字号、圆角、内容宽度、区块间距只通过 CSS 变量（Web：`var(--c-primary)` 等，在 `assets/css/tokens.css`；Elementor：绑定 Global Colors），不要写死 hex。
3. 模板里的文案和图片都是占位：必须换成客户真实内容；没有素材的位置标「缺图」。
4. 出稿前过 `README.md` 里的「反普通清单」。
5. 中文内容必须配中文 fallback（Noto Sans SC / Noto Serif SC），中文标题不要斜体。
6. 页面转场只用 View Transitions API（`get_transition`）；告诉用户它在 Chrome/Edge 126+、Safari 18.2+ 才有动画，其它浏览器正常跳转。

## 授权红线
- `local_only`（LuxeNest kit 与 `luxenest-*` 零件，来自 Envato Elements；以及任何 `--license local_only` 入库的模板）：每个新客户项目要在 Envato 登记授权；**不可转售、不可公开分发**。只用本地路径读取，不要把内容贴到公开网站/仓库。它们不会进入 `public_html`（构建时自动排除）。
- 授权不明的资源只放 `_work/inbox/`，不入库。

## 收集模板（从本地文件夹 / 连接 / 导出文件）
用户会说「把 ~/xxx 文件夹里的模板收进库」或给你一个连接（Google Drive / Notion / Figma / 某个 URL）。流程：

### 1. 找到来源
- **本地文件夹**：递归找 `index.html`（或 `index.php`）所在目录；**一个目录 = 一个模板**。
- **Design Library 导出文件**：`*.site.json`（`design-library-site@1`）、`*-html-site.zip`、`*-php-site.zip`。
- **连接**：先用对应工具列出文件并下载到 `_work/inbox/<来源名>/`，再按本地文件夹处理。Figma 稿只提取 tokens（颜色/字体/圆角）和结构，不要凭截图硬抄 HTML。
- 先放 `_work/inbox/`，确认授权后才入库。

### 2. 判断授权（唯一必问）
自己做的 / 开源可再分发 → `--license ok`；Envato、ThemeForest、付费主题 → `--license local_only`；不清楚 → 停下来问用户。

### 3. 入库
```
python tools/ingest_template.py <文件夹 | .zip | .site.json> --slug <kebab-case> --name "Name" --zh 中文名 \
    --types company,landing --ind restaurant --styles warm,playful [--license local_only] [--replace]
python build/build.py
```
- `.site.json` → **完整可定制模板**（format=fragments）：网站里可继续换色、字体、宽度、转场。
- 文件夹 / zip → **Imported 整页模板**（format=documents）：本地 CSS/JS 内联、小图片转 data URI、内部链接改成 `{{p:slug}}`（首页 `{{p:home}}`）；网站里可预览、复制、下载，但不能换色（改它自己的 CSS）。PHP 站（`includes/header.php`+`footer.php`）会合并成整页。
- 入库后目录：`library/templates/<slug>/{template.json, nav.html, footer.html, pages/*.html, TEMPLATE.md}`；`library/templates/order.json` 决定展示顺序。

### 4. 分类 ID（只用 `library/taxonomy.json` 里的，不要自造；不认识的 ID 脚本会报错）
- **types**：company landing ecommerce portfolio blog
- **industries**（31）：corporate saas agency fashion media restaurant health fitness construction realestate education medical nonprofit photography events travel automotive legal tech music finance beauty pets agriculture logistics interior gaming government homeservices faith coworking
- **styles**（30）：minimal editorial bold elegant corporate playful dark organic retro glass neobrutal swiss geometric warm futuristic photo typographic pastel monochrome maximal clay aurora bento artdeco scandi japanese y2k handdrawn darkluxury earthy
- 页面 `group`：Main Shop Proof Content Special Utility
- 需要新分类：改 `library/taxonomy.json` 再 `python build/build.py`。

### 5. 收完之后
1. 列出缺的常见页（about、services、pricing、contact、404…），告诉用户。
2. 列出外部 CDN 字体/图片，提醒是否要本地化。
3. 回报：收了几个模板、各几页、授权状态、缺什么。**不要**把 `local_only` 内容贴到公开处。

## 往库里加效果 / 转场 / 色板
- **效果**：`library/effects/<分类>/<slug>/`：`effect.json`（slug cat name zh tech tag bleed css html js）、`snippet.html`（贴进去就能用）、`EFFECT.md`。只能用 CSS 变量 `--primary --secondary --text --accent --surface --border --font-heading --font-body --radius --scale --speed --on-primary --on-accent`，带 `prefers-reduced-motion` 降级，交互元素可键盘操作；并把 slug 追加到 `library/effects/order.json`。
- **转场**：`library/transitions/<slug>/{transition.json, transition.css}`（变量 `--pt-dur --pt-ease --pt-color`）；追加到 `transitions/order.json`。
- **色板**：`library/palettes/palettes.json`，顺序 `[primary, secondary, text, accent, surface, border]`，需过对比度（正文/底色 ≥ 4.5，主色/底色 ≥ 4.5）。
- 改完都跑 `python build/build.py`；MCP 现读文件不用重启（目录已更新）。

## 滚动动画词汇（给 AI 描述滚动效果时用这 6 个词，对应 `library/effects/scroll/`）
| 词 | 意思 | 效果 slug |
|---|---|---|
| Scroll-triggered 滚动触发 | 进入视口时播一次 | `scroll-reveal` |
| Scroll-linked 滚动连动 | 动画进度绑定滚动位置，回滚会倒放 | `scroll-linked-text-fill`、`scroll-progress-bar` |
| Parallax 视差滚动 | 不同图层不同速度 | `scroll-parallax-layers`、`hero-parallax` |
| Sticky 固定置顶 | 元素滚到顶部后黏住 | `scroll-sticky-index`、`header-sticky-shrink` |
| Scroll Snap 滚动吸附 | 滚动停在整屏/整块上 | `scroll-snap-sections`、`carousel-snap` |
| Horizontal Scroll 横向滚动 | 纵向滚动驱动横向移动 | `scroll-horizontal-pin` |

## 新建内容必须独特（必守）
新建 template / effect / page transition 前，先查 `library/catalog.json` 里已有的条目，**不得与已有的太相似**：
- **template**：每个模板在以下维度都要与库里**所有**已有模板明显不同（不只是同行业的）：风格、字体（标题+正文组合不重复）、配色（主色相不同）、排版构图（导航形式、首屏结构、商品/内容列表形式、详情页结构、页脚）、内容（文案口吻、栏目、页面清单、微文案）。不能只换颜色和文案。每个模板要写自己的专属 CSS（放在 `nav.html` 的 `<style>` 里，类名用模板前缀，只用 CSS 变量），并有自己的 `DESIGN.md`（构图特征 + 不要清单）。
- **effect**：必须是新的交互 / 视觉机制，不是已有效果换参数。已有的先看同分类里的 slug，机制相同就不新建。
- **page transition**：必须是新的转场动画方式（运动轨迹 / 遮罩形状 / 时序），不能只是已有转场换方向或换颜色。
- 新建前在回复里写一句「与最接近的已有项相比，不同在哪」；做不出明显差异就不建。
- 需要新分类（如 sports、furniture、massage）先改 `library/taxonomy.json`。

## 性能与预览（缩略图 / 精简数据 / Live 层）
- **静态缩略图**：网站首页的模板和效果卡片用 `library/previews/t-<slug>.jpg`、`e-<slug>.jpg`（640×400），不再每张卡片放一个 iframe。新增或改动模板 / 效果后：`python build/build.py` → `python tools/gen_previews.py`（只重拍有变化的）→ 再 `python build/build.py`。没有缩略图的项目会自动回退到 iframe。
- **精简数据**：有缩略图的模板在 `data/manifest.json` 里不再内联 nav / foot / 首页（点开时读 `api/templates/<slug>/<slug>.json`）；效果的 css / html / js 放在 `api/fx/<slug>.json`（必须在公开的 `api/` 下：`data/` 被 .htaccess 禁止浏览器直接访问），点开时再读。manifest 约 230 KB（gzip 约 50 KB），原来 1.1 MB。
- **Live 层**（让模板预览「活」起来）：`library/runtime/live.js` + `live.css`，只用于预览（顶栏「✦ Live」可开关）；模块：reveal 滚动淡入 / count 数字滚动 / lift 悬停上浮 / progress 阅读进度条 / parallax 视差 / headline 标题逐词 / magnetic 磁吸按钮 / tilt 卡片倾斜 / cursor 光标环。按风格自动挑选，或在 `library/runtime/live-map.json` 里手动指定：`{"模板slug": ["reveal","count"]}`。尊重 `prefers-reduced-motion`；手机端不加载鼠标类模块。
- **页面分组**：模板 `pages[].group` 可以用任意名称（如 Café / Garage / Clinic），预览顶栏的页面下拉会自动按分组显示。

## 手机端 / 触屏（必守）
新建或改动任何 template / effect / 网站界面（`build/src/app.*`）后，都要过手机端检查：
- **宽度**：390px（手机）和 768px（平板）下不能出现横向滚动；根元素有 padding 时用 `box-sizing:border-box`（效果基础样式已含 `.fx{box-sizing:border-box}`）。
- **触屏没有悬停**：凡是用 `:hover` 显示 / 改变内容的效果，必须在触屏上也有效。效果基础工具 `tools/fx_touch_patch.py` 会把每个 `:hover` 规则复制成 `.is-tap`，并在触摸时给被点元素加 `.is-tap`；靠 `mousemove` 的效果要另写触摸版本（按下 / 拖动 / 点击涟漪）。光标类效果（`cursor-*`）在触屏上用点击涟漪或爆点代替。
- **触摸目标 ≥ 44px**：触屏下按钮、输入框、下拉最小 44px（基础样式已带 `@media (pointer:coarse)` 规则）；导航链接也要有足够的点击面积。
- **字号 ≥ 12px**，不依赖 hover 才能看见的重要信息，不用 `100vh` 做固定高度（用 `min-height`）。
- 自动检查：`python tools/mobile_audit.py`（效果 + 模板首页）、`--templates --all-pages`（模板每一页）、`--width 768`。有问题时退出码为 1。
- 新增效果后运行一次 `python tools/fx_touch_patch.py`（幂等），再 `python build/build.py`。

## 源库同步（必守）
**`Design Library/library/` 是唯一源头，必须与任何新增 / 改动的 template、effect、page transition、色板实时一致。** `public_html/` 只是 build 产物，不要只改 `public_html/`。
- 无论改动发生在哪里（`public_html/`、网站、MCP、其它项目），都要同步回 `library/`（`templates`、`effects`、`transitions`、`palettes`，并更新对应的 `order.json` / `taxonomy.json`），再跑 `python build/build.py`。
- 同步后更新本文件开头的数量（模板 / 效果 / 转场 / 色板），并按下一节规则列出需上传文件、追加「上传记录」。
- 回复结尾说明：`library/` 已同步了哪些条目。

## 上传到 Hostinger 的记录（必守）
**每次 `public_html/` 有更新（跑过 build / 改过文件）之后，必须在回复里列出「哪些文件有改动、需要上传到 Hostinger」，并把清单追加到 `UPLOAD_LOG.md`（最上面）。** 做法：build 前给 `public_html/` 做 MD5 快照，build 后比对，分成 新增 / 修改 / 删除 三类。
注意：
- Windows 下 build 写出的是 CRLF，`api/downloads/*.zip` 每次 build 字节都可能不同，哈希会大面积「变动」；只把**内容真的变了**的文件列为必传，其余说明「仅字节差异，可不传」。
- `build.py` 已改成只清子项并保留 `public_html/.vscode/`（2026-10-12 起）。
- 如果 `build.py` 因 `public_html` 只读属性报 `PermissionError`（Google Drive 造成），先清掉只读属性再重跑（PowerShell：对 `public_html` 递归去掉 ReadOnly，包括根目录本身）。
- **build 会清空整个 `public_html/`**（包括放在里面的 `.vscode/sftp.json`），所以 sftp 配置必须放在项目根目录 `.vscode/sftp.json`，不要放进 `public_html/`。
- 如果 build 报 `WinError 32`（终端的工作目录正好在 `public_html` 里，根目录删不掉），不要重复硬跑：这时 build 已经把里面的内容清空了，需要用「保留根目录」的方式重跑 build（把 `shutil.rmtree` 换成只删子项），然后再做 MD5 比对。
- 最保险：用 `python build/deploy.py`，或把整个 `public_html/` 打 zip 在 Hostinger 解压。
